## Invitations
Use native Supabase Auth admin invitations, not a browser-side code or a client secret. Admin confirms adult pilot participant and consent information before sending an individual email via Authentication > Users > Add user > Send invitation. Verify recipient, allowed redirect URL, email delivery/SMTP and configured link expiration. Never put admin keys into Gyste. A confirmed existing account should keep its usual login.
After verifying whether other applications share this Auth project, disable public signups and anonymous sign-ins in server settings in the isolated environment first. The admin invitation route must be tested with signup disabled. The preview hides public signup but this is NOT server enforcement. Existing production signup is unchanged.
Tests: unauthenticated direct signup denied; authorized invitation reaches correct email; expired/reused invite rejected; non-invited address denied; existing login and recovery work; invitation sets password or uses recovery; no alternative OAuth/OTP/anonymous signup bypass. Admin invite email delivery may need custom SMTP. No extra service approved.
Docs: https://supabase.com/docs/guides/auth/general-configuration ; https://supabase.com/docs/guides/auth/users

## Account erasure
Existing table gyste_account_deletion_requests is a request queue, not full deletion. Verified metadata: most references to auth.users cascade; notifications.actor_id and spaces.owner_id set null; messages may cascade on either participant; posts.repost_of cascades. Six buckets exist: gyste-chat-media, gyste-media, gyste-private-media, gyste-profile-images, gyste-story-media, legacy media. Public buckets remain public until deletion. Inventory other references, including arrays, text links, legacy tables, reports, media ownership, backups and local IndexedDB across devices. Do not delete storage.objects using SQL: use Storage API.
Proposed controlled workflow: verify requester and pending request; stop new writes and revoke sessions (including still-valid tokens); inventory all files and references; create durable admin-only cleanup job with minimal metadata, audit status and legal retention rules; delete verified owned files through Storage API with retry and checks; process dependent data with an approved retention policy, then Auth admin deletion; verify zero residual owned media and relevant records; notify requester via verified channel. Keep other users' data unless a reviewed policy requires deletion; do not delete live data without explicit request. Test entirely on synthetic accounts before enabling. No destructive operation in this change.
